# Keynote HTML HiDPI Patch

Improve the rendering quality of Apple Keynote HTML exports on high-DPI displays while preserving animations and transitions.

An unofficial, dependency-free Python utility that patches Keynote's exported HTML player to render PDF content and animated elements at higher resolutions.

## Why?

Keynote can export presentations as standalone HTML, allowing them to be played in a web browser without PowerPoint or Keynote installed. Unlike PDF exports, HTML presentations retain many of Keynote's animations and transitions, including Magic Move.

However, exported presentations may appear blurry, especially on Retina and other high-DPI displays.

The HTML player uses PDF.js to rasterize slide elements into HTML canvases. In Keynote 15.4, certain rendering paths use a fixed 1× pixel density, regardless of the display's device pixel ratio. Animated elements also use separate Canvas and WebGL rendering paths, which can result in reduced sharpness when objects appear or transitions complete.

This utility patches those rendering paths to use higher-resolution backing buffers while preserving the original logical dimensions of the presentation.

## Features

- **Sharper text and graphics:** Increase PDF.js rendering resolution to 2× or 3×.
- **Improved animated elements:** Apply high-DPI rendering to WebGL animations, Smart Build canvases, and content transitions.
- **Preserve animations:** Keep Keynote's original HTML presentation structure and animation logic.
- **In-place patching:** Modify only `assets/player/main.js`, leaving slide assets and presentation data untouched.
- **Idempotent:** Run the script repeatedly without accumulating scaling changes. Switch between 2× and 3× as needed.
- **No dependencies:** Uses only the Python standard library.
- **Fail-safe matching:** Reject unsupported player structures rather than applying potentially unsafe substitutions.

## Requirements

- Python 3.10 or later
- An HTML presentation exported from **Apple Keynote 15.4**

No third-party Python packages are required.

## Usage

### 1. Export your presentation

In Keynote, choose **File → Export To → HTML**.

The exported directory should contain a structure similar to:

```text
My Presentation/
├── index.html
└── assets/
    └── player/
        └── main.js
```

### 2. Apply the patch

Run the script with the path to the exported HTML **directory**, not the HTML file itself.

```bash
python3 patch_keynote_html.py "/path/to/My Presentation"
```

The default rendering scale is **2×**.

To explicitly select a scale:

```bash
python3 patch_keynote_html.py "/path/to/My Presentation" --scale 2
```

For higher pixel density:

```bash
python3 patch_keynote_html.py "/path/to/My Presentation" --scale 3
```

On Windows:

```powershell
py -3 patch_keynote_html.py "C:\path\to\My Presentation" --scale 2
```

### 3. Open the presentation

Open `index.html` in your preferred browser, such as Chrome, Edge, or Safari.

No additional server or runtime is required by the patch.

## How It Works

The exported Keynote HTML player uses multiple rendering paths:

| Rendering path | Modification |
|---|---|
| PDF.js | Increases the rendering scale for PDF-backed slide content |
| Canvas cropping | Adjusts source coordinates and CSS dimensions for high-resolution content |
| WebGL animations | Increases drawing-buffer resolution while preserving logical slide coordinates |
| WebGL framebuffers | Restores the appropriate viewport when rendering to the default framebuffer |
| Smart Build | Increases the backing resolution of independently created animation canvases |
| Contents animations | Avoids unnecessary CSS scaling of high-resolution canvas content |

For example, a 1920 × 1080 canvas rendered at 2× uses a 3840 × 2160 backing buffer while retaining its original displayed dimensions.

**This does not enable true vector rendering.** PDF-based elements are still rasterized, but at a higher resolution.

## Compatibility

This patch is specifically designed for the minified HTML player generated by **Keynote 15.4**.

It supports:

- Original, unmodified Keynote 15.4 HTML exports.
- Exports modified by the earlier PDF-only 2×/3× patch.
- Exports already modified by this script.

If the requested scale has already been applied, the script makes no changes.

Apple may change the internal HTML player implementation between releases. Because this utility relies on exact matches against the generated JavaScript, other Keynote versions are not guaranteed to work.

An unsupported or unexpected player structure causes the script to exit with an error rather than blindly modifying the file.

## Limitations

**Performance:** Higher rendering resolution increases memory usage and GPU workload. A 2× canvas has four times as many pixels as a 1× canvas; a 3× canvas has nine times as many. Large presentations or complex animations may experience higher memory consumption or reduced performance.

**Version dependence:** The patch targets undocumented Keynote player internals and may require updates for future Keynote releases.

**Browser differences:** Rendering quality and animation behavior may vary across browsers, graphics drivers, and display configurations.

**Testing:** The patch has been structurally checked against a Keynote 15.4 export. Comprehensive browser-level regression testing across all Keynote animation effects has not been completed.

**No automatic backup:** The script atomically replaces `assets/player/main.js` in place. It does not create a backup file. Keep an unmodified copy of your export or re-export from Keynote if you need to restore the original player.

## Troubleshooting

**Unsupported player error**

Verify that the presentation was exported from a compatible Keynote version. The script intentionally refuses to patch unrecognized JavaScript structures.

**The presentation still looks blurry**

Make sure you patched the correct export directory, reload the presentation, and compare it at the same browser zoom and display resolution. Some rendering effects may use paths not yet covered by the patch.

**An animation behaves incorrectly**

Restore an original export and verify whether the problem also occurs without the patch. When reporting an issue, include the Keynote version, browser, operating system, rendering scale, and affected animation type.
